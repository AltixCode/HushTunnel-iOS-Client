# HushTunnel iOS Client — 4.3(a) Design Spam Remediation Plan

## Background & Diagnosis
HushTunnel (`com.hushtunnel.ios`, App Store Connect ID: `6807551411`) has received multiple rejections under **Guideline 4.3(a) – Design – Spam**:
> "We noticed the app shares a similar binary, metadata, and/or concept as apps submitted to the App Store by you or other developers, with only minor differences... Creating and submitting multiple similar apps using a repackaged app template... Purchasing an app template with problematic code from a third party."

### Exact Root Causes Found in the Codebase
1. **Fork Fingerprint & Dead Stock Code**:
   `HushTunnel-iOS-Client` was forked from `SagerNet/sing-box-for-apple` (`io.nekohasekai.sfi`), which is already an active App Store client published by `nekohasekai`. Although [`Application.swift`](file:///Users/ata/Dev/mobile_native_apps/HushTunnel-iOS-Client/SFI/Application.swift) was updated to render [`RootView()`](file:///Users/ata/Dev/mobile_native_apps/HushTunnel-iOS-Client/ApplicationLibrary/HushTunnel/Views/RootView.swift), **the entire stock upstream UI remains in the binary target (`SFI`)**:
   - `MainView.swift` (stock 5-tab root view with Dashboard, Profiles, Connections, Logs, Settings)
   - Stock code editor views and wrappers (`ProfileEditorWrapperView.swift`, `GhosttyConfigEditorWrapperView.swift`, `RunestoneTextView.swift`, `ProfileEditorTheme.swift`)
   - Complete stock view hierarchies in `ApplicationLibrary/Views/` (`Dashboard/`, `Profile/`, `Setting/`, `Tools/`, `Connections/`, `RemoteControl/`, `Scanner/`)
   - Heavy unused third-party syntax-highlighting frameworks: `Runestone` and `TreeSitterJSON5`.

2. **Literal `sing-box` Strings & System Identifiers**:
   Apple's automated binary & manifest analysis flags literal strings and identifier matches:
   - [`SFI/Info.plist`](file:///Users/ata/Dev/mobile_native_apps/HushTunnel-iOS-Client/SFI/Info.plist#L33): `NSUbiquitousContainerName` is `"sing-box"`.
   - [`SFI/ApplicationDelegate.swift`](file:///Users/ata/Dev/mobile_native_apps/HushTunnel-iOS-Client/SFI/ApplicationDelegate.swift#L106): `NSFileProviderDomain` registers `displayName: "sing-box"`.
   - [`sing-box.xcodeproj/project.pbxproj`](file:///Users/ata/Dev/mobile_native_apps/HushTunnel-iOS-Client/sing-box.xcodeproj/project.pbxproj#L2697): `INFOPLIST_KEY_NSLocalNetworkUsageDescription` states *"As a universal proxy platform, sing-box configures routing according to your configuration."*
   - Project directory itself is still named `sing-box.xcodeproj`.
   - Upstream Bonjour / NWListener application services registered with name `sing-box:profile` and `sing-box:report-transfer`.

3. **Mach-O Binary Similarity Graph**:
   Apple's static analyzer compares symbol tables and Mach-O structure against existing App Store binaries. Since 90% of the compiled Swift code in `SFI` matches `io.nekohasekai.sfi` byte-for-byte, Apple's classifier marks it as a repackaged clone.

---

## Actionable Remediation Plan

### Step 1: Purge Unused Upstream Code & Frameworks
- Remove `MainView.swift`, `ProfileEditorWrapperView.swift`, `GhosttyConfigEditorWrapperView.swift`, `RunestoneTextView.swift`, and `ProfileEditorTheme.swift` from `SFI/`.
- Remove `Runestone` and `TreeSitterJSON5Runestone` dependencies from the project and targets.
- Remove `Frameworks/Runestone` and `Frameworks/TreeSitterJSON5`.
- Remove dead upstream views from `ApplicationLibrary/Views/` that HushTunnel never navigates to, while retaining core helpers (`DeviceCensorship`, `LogView`, `URLQRCodeSheet`, `ExternalQRCodeView`, etc.).

### Step 2: Scrub All Upstream `sing-box` Identifiers
- In [`SFI/Info.plist`](file:///Users/ata/Dev/mobile_native_apps/HushTunnel-iOS-Client/SFI/Info.plist): change `NSUbiquitousContainerName` to `HushTunnel`.
- In [`SFI/ApplicationDelegate.swift`](file:///Users/ata/Dev/mobile_native_apps/HushTunnel-iOS-Client/SFI/ApplicationDelegate.swift): change `NSFileProviderDomain` display name to `HushTunnel`.
- In `project.pbxproj` and target configurations:
  - Update `INFOPLIST_KEY_NSLocalNetworkUsageDescription` to:
    `"HushTunnel configures secure network routing according to your selected edge endpoint."`
- Update service listener names in `ApplicationLibrary/Service/` from `sing-box:*` to `hushtunnel:*`.

### Step 3: Rename Project Container & Update Toolchain Scripts
- Rename `sing-box.xcodeproj` to `HushTunnel.xcodeproj`.
- Update references in:
  - `.github/workflows/ios-release.yml`
  - `fastlane/Fastfile`
  - `fastlane/Snapfile`
  - `scripts/test-ios-e2e.sh`
  - `AGENTS.md` and `HANDOFF.md`

### Step 4: Verification & Git Commit
- Verify `project.pbxproj` parses cleanly.
- Run typecheck / build validation.
- Commit all changes with clear rationale and push to `origin` and `forgejo`.
